# RAG Document Q&A Chatbot

A Retrieval-Augmented Generation chatbot that lets users upload PDF documents and ask questions about their content in natural language. The backend chunks and embeds documents, stores the vectors in Chroma, and retrieves the most relevant passages to ground responses generated by the Google Gemini API through LangChain. Answers stream back to the client token by token over Server-Sent Events.

## Features

- Upload one or more PDF documents and index them for semantic search
- Automatic text extraction, chunking, and embedding generation
- Vector similarity search against a Chroma database for accurate context retrieval
- Real-time, token-by-token streaming responses using Server-Sent Events
- Source attribution showing which file and page an answer was drawn from
- Scope questions to a single document or search across all uploaded documents

## Tech Stack

| Layer | Technology |
| --- | --- |
| LLM orchestration | LangChain (JavaScript) |
| Language model & embeddings | Google Gemini API |
| Vector database | Chroma |
| Backend | Node.js, Express |
| Frontend | React, Vite |
| Streaming transport | Server-Sent Events (SSE) |
| Deployment | Docker, Docker Compose |

## Architecture

```
frontend (React)  --->  backend (Express)  --->  Gemini API (embeddings + chat)
                              |
                              v
                        Chroma vector store
```

1. A PDF is uploaded to the backend and parsed with `pdf-parse`.
2. The document is split into overlapping chunks with LangChain's recursive text splitter.
3. Each chunk is embedded with the Gemini embeddings API and stored in Chroma alongside file and page metadata.
4. When a user asks a question, the backend embeds the query, retrieves the top matching chunks from Chroma, and passes them to the chat model as context.
5. The chat model's response streams back to the browser over SSE and renders incrementally.

## Prerequisites

- Node.js 18 or later
- A Google Gemini API key (free tier available at aistudio.google.com/apikey)
- Docker and Docker Compose (for containerized deployment)

## Local Development (without Docker)

Requires Node.js 18+ and Python 3.9+ (Python is only used to run Chroma).

### 1. Configure environment files

```bash
cp backend/.env.example backend/.env
cp frontend/.env.example frontend/.env
# add your GOOGLE_API_KEY to backend/.env
```

### 2. Install Chroma (Python package)

```bash
pip install chromadb
```

### 3. Install all Node dependencies (root, backend, frontend)

From the project root:

```bash
npm install
npm run install:all
```

### 4. Run everything with a single command

```bash
npm run dev
```

This starts Chroma (port 8000), the backend (port 5000), and the frontend (port 5173) together in one terminal, each with a labeled, color-coded log prefix. Press `Ctrl+C` once to stop all three.

Individual pieces can still be run on their own if needed:

```bash
npm run chroma
npm run backend
npm run frontend
```

The app is available at `http://localhost:5173`.

## Running with Docker Compose

```bash
cp .env.example .env
# add your GOOGLE_API_KEY to .env
docker compose up --build
```

This starts Chroma, the Express backend, and an nginx-served React build. The app is available at `http://localhost:5173`.

## API Reference

### `POST /api/documents/upload`

Uploads and indexes a PDF. Accepts `multipart/form-data` with a `file` field.

Response:
```json
{
  "message": "Document processed and indexed successfully.",
  "document": {
    "sourceId": "uuid",
    "fileName": "example.pdf",
    "pageCount": 12,
    "chunkCount": 34
  }
}
```

### `DELETE /api/documents/:sourceId`

Removes all indexed chunks belonging to a document.

### `POST /api/chat/stream`

Streams a grounded answer over Server-Sent Events.

Request body:
```json
{
  "question": "What does the document say about pricing?",
  "history": [{ "role": "user", "content": "..." }, { "role": "assistant", "content": "..." }],
  "sourceId": "optional-uuid-to-scope-to-one-document"
}
```

Emitted events: `token` (incremental text), `sources` (retrieved passages used), `done` (stream complete), `error`.

### `GET /api/health`

Basic liveness check.

## Environment Variables

| Variable | Description | Default |
| --- | --- | --- |
| `PORT` | Backend server port | `5000` |
| `GOOGLE_API_KEY` | Google Gemini API key | required |
| `CHROMA_URL` | Chroma server URL | `http://localhost:8000` |
| `CHROMA_COLLECTION_NAME` | Chroma collection name | `rag_documents` |
| `EMBEDDING_MODEL` | Gemini embedding model | `gemini-embedding-001` |
| `CHAT_MODEL` | Gemini chat model | `gemini-2.5-flash` |
| `CHUNK_SIZE` | Characters per chunk | `1000` |
| `CHUNK_OVERLAP` | Overlap between chunks | `150` |
| `TOP_K_RESULTS` | Number of chunks retrieved per query | `4` |
| `MAX_FILE_SIZE_MB` | Maximum upload size | `15` |
| `CORS_ORIGIN` | Allowed frontend origin | `http://localhost:5173` |

## Deployment Notes

- The backend and Chroma each need persistent storage in production; the provided `docker-compose.yml` mounts a named volume for Chroma data.
- Set `CORS_ORIGIN` to the deployed frontend URL.
- Set `VITE_API_BASE_URL` in the frontend environment if the API is served from a different origin than the frontend.
- Rotate and store the Gemini API key using your hosting provider's secret manager rather than committing it to source control.
